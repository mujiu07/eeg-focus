## 1. 决策记录（Decision Log）

> 格式：背景 → 决策 → 代价/边界 → 证据 → 状态
> 状态：`已采纳`（当前代码遵循）/ `已修订`（后续被新决策覆盖）/ `待定`

### D-001 本地优先、无账号、无云端

- **背景**：目标用户是儿童，脑电属于敏感数据；课程场景也不需要多用户。
- **决策**：所有脑电处理与报告落盘都在本机；不建账号、不做云同步；服务只监听 `127.0.0.1`。
- **代价**：换设备/清缓存即失去本地进度；家长分享报告需手动导出文件。
- **证据**：脑电链路无出站调用（`app/music.py` 例外，仅背景音乐）；`web/` 无外部静态资源；`usage-and-privacy.md` §6。
- **状态**：已采纳。

### D-002 FastAPI + SSE + 单进程

- **背景**：需要 REST、实时推流、静态托管与 Python 算法同栈。
- **决策**：单 FastAPI 进程承载全部能力；实时用 `EventSourceResponse`，0.5 s/帧。
- **代价**：无多用户并发与持久队列；长任务需注意事件循环阻塞（EDF 加载放线程池）。
- **证据**：`app/server.py`；`web/assets/api.js`；`ARCHITECTURE.md` §6。
- **状态**：已采纳。

### D-003 零构建原生前端

- **背景**：儿童场景要求秒开、低依赖；团队不引入 Node 工具链。
- **决策**：原生 HTML/CSS/JS + Canvas；公共能力放 `web/assets/`。
- **代价**：无组件化框架，复杂状态靠约定；样式复用需自律。
- **证据**：仓库无 `package.json`；5 个页面共用 `assets/`。
- **状态**：已采纳。

### D-004 模型优先 + 频段回退

- **背景**：训练模型基于 21 通道 EDF；消费级 Xmuse 只有 4/6 通道。
- **决策**：维度匹配走 231 维 LogisticRegression；不匹配或推理异常时回退 `β/(θ+α)` + sigmoid；两者共用 EMA。
- **代价**：4 通道只表达相对变化，非临床指标；两套口径需在文档中讲清。
- **证据**：`app/focus_engine.py`；`tech-stack.md` §4；`train_report.md`。
- **状态**：已采纳。

### D-005 个人基线（P50）+ 1 小时有效期

- **背景**：绝对专注值跨被试差异大，直接用固定阈值不可解释。
- **决策**：校准 40 s（安静 20 s + 心算 20 s），取 focus 中位数；基线存 `bf-calib`，1 h 有效；同时记录 P10/P90。
- **代价**：校准状态影响当天体验；过期需重校；短时校准可能不稳定。
- **证据**：`app/server.py` `/calibrate`；`web/calibrate.html`；`PRD` 业务规则表。
- **状态**：已修订（v1.8.2 由 D-023 的“每日自然/教学 + 双基线”取代；旧 P50 仅保留为历史实现说明）。

### D-006 动态 20–80 分映射：报告 50 分线、游戏 42 分零点

- **背景**：0–1 的 focus 对家长/孩子不直观；固定 ×100 会让校准差异失真。
- **决策**：用校准两端 `score_low/score_high` 线性映射到 20–80 分（越界钳到 0–100）；未校准时用 0.35/0.75 兜底；报告以两端中点（50 分）为"高于基线"线；游戏蓄力以 42 分为零点，45/38 为专注灯开关阈值（v1.4.2 放宽）。
- **代价**：换基线后同一 focus 的分数会变；跨会话比较需看相对值；报告与游戏两套阈值容易被误读，文档需写明。
- **证据**：`app/server.py` `score_of()`、`raw50()`；报告字段 `score_range`。
- **状态**：已采纳。

### D-007 蓄力/起跳与计分：+2 / +1，得分即积分

- **背景**：v1.4.15 之前商城与得分两套计数，家长与孩子都困惑。
- **决策**：金色区间主动起跳 +2，蓄满自动 +1；本局得分直接作为积分一次性入账。
- **代价**：不再按起跳次数单独计分；历史报告的旧口径需按字段回退。
- **证据**：`web/game.html`（`state.score += perfect ? 2 : 1`）；`wallet.js`；`CHANGELOG` v1.4.15。
- **状态**：已修订（v1.5.0 起由 D-018 的潜在得分 / 点击兑现取代）。

### D-008 Xmuse 走 OSC/UDP，默认端口 7000/8000

- **证据**：`app/xmuse_osc.py`；`docs/xmuse-hardware-integration.md`；探针脚本。

### D-016 去噪去伪迹：带通减除眨眼 + 掩码排除坏道，不改特征口径

- **背景**：Xmuse 干电极前额通道上，眨眼幅值常为 β 波的 10 倍以上；原链路只有 0.5–45 Hz 带通，拦不住眨眼，专注分会被眨眼瞬间抬高。
- **决策**：新增 `app/denoise.py`，在 hardware 源出窗后做「去趋势 → 50 Hz 陷波 → 伪迹检测 → 修复 → 质量评分」。眨眼用 `0.5–8 Hz` 分量迭代 2 次减除；削顶段 ≤0.3 s 才插值；坏道以 `channel_mask` 排除；伪迹过重的窗判 `usable=false`，不出分、不入 history。**不做 0.5–45 Hz 带通**，保持与训练/`prepare_signal` 同一口径。
- **备选与否决**：段内线性插值（beta −21%）、`0.5–15 Hz` 带通减除（alpha −20%）、坏道置零（拉低 β 相对功率）——均实测不达标。
- **代价**：眨眼残留约 45%（只影响形态不影响频段功率）；阈值需真机标定；每个窗口增加一次陷波与 2 次滤波开销（2 s 窗口下可忽略）。
- **证据**：`tests/selfcheck_denoise.py`（10 项）、`tests/e2e_hardware_denoise.py`；`docs/denoise-artifacts.md`。
- **状态**：已实现；真机阈值标定未做。

### D-017 运动伪迹：台阶/共模修，慢摆拒绝

- **背景**：干电极贴前额，头动与线缆晃动会产生三类东西——电极极化突变造成的 DC 台阶、0.5–3 Hz 大幅摆动、全通道同向的共模偏移。原来的链路只有线性去趋势，而线性去趋势会把阶跃变成一条大斜率，等于把台阶藏进低频。
- **决策**：① 共模与台阶放在**去趋势之前**处理；② 台阶用首尾 0.25 s 中位数差判定（脉冲型眨眼会回零，不算台阶），并用 sigmoid（0.05 s 过渡）构造跃变基线减除；③ 共模超过 55 µV 且显著大于通道间残差时减 80%；④ **0.5–3 Hz 慢摆只识别不修复**，直接 `usable=false`。
- **关键理由**：慢摆与 θ 重叠，减掉它会削小 `β/(θ+α)` 的分母，制造假专注分。"宁可不出分，不出假分"优先于帧率。
- **代价**：佩戴不稳时会出现较多不可用帧；台阶若正好落在窗口正中、首尾都干净，会被首尾差漏掉（靠削顶/慢摆兜底）。
- **证据**：`tests/selfcheck_denoise.py` 用例 11–14；`docs/denoise-artifacts.md` §2.2/§6.1。
- **状态**：已实现；真机阈值标定未做。

### D-018 单轮计分：游戏积分与商城货币分离（v1.5.0）

- **背景**：旧版主动 +2 / 自动 +1 的区分度太低，且自动起跳也能得分；单跳得分放大到 20–100 后，若直接当积分会冲垮 5–18 积分的商城定价。
- **决策**：每轮唯一金色区域，进入时用 `round(20 + 80×T_ref/(T+T_ref))` 锁定脑电基础分 B，点击兑现、错过 0 分；商城积分改为 `max(1, floor(本局游戏积分/30))`。宽容期 1.5 s、衰减速度 `V_ref×0.30`、子弹时间 2.5 s 全部集中在 `web/assets/focus-round.js` 的 `CONFIG`。v1.6.0 由 D-019 补充点击时机折损与无效点击冷却。
- **代价**：报告同时出现“脑电基础分”“实际积分”“商城积分”三个口径，需要在文案与导出里明确区分；旧会话 JSON 没有 `actions.rounds`，报告按缺失字段回退。
- **证据**：`web/assets/focus-round.js`、`web/game.html`、`app/server.py` `RoundRecord`、`app/export.py`「每轮数据」、`tests/selfcheck_round_logic.js`。
- **状态**：已采纳（覆盖 D-007 的计分与积分口径）。

### D-019 点击时机折损与无效点击冷却（v1.6.0）

- **背景**：v1.5.0 在金色区域内任意位置点击都拿满基础分，点击时机没有行为区分；同时非金色区域连续点击/长按不产生成本，可能被用来刷蓄力时间或制造输入噪声。
- **决策**：
  - 进入金色区域后的前 **0.6 s** 点击拿 100% 脑电基础分；之后线性下降，窗口结束前最多折损 **10%**；超过 2.5 s 为 0。`S = round(B × M(t))`，不改变 `B` 的脑电主导地位。
  - 非金色区域点击触发 **0.5 s 蓄力冷却**：暂停增长、继续计入本轮用时、不额外衰减、不扣分、不清空、不跳跃；冷却中重复点击不叠加/不延长。
  - 儿童端隐藏实时脑电分、蓄力百分比、BPM、信号质量与潜在分，只显示本局累计积分和成功后的 “+N”；开发者模式保留全部数字。
- **代价**：点击时机带来最多 10% 的分数折损，但仍是行为响应指标，不能当作真实注意力；冷却会让提前点击间接降低基础分，需要向家长解释“不是扣分”。
- **证据**：`web/assets/focus-round.js` 的 `timingMultiplier` / `actualScore` / 冷却逻辑，`tests/selfcheck_round_logic.js` 36 项、`tests/selfcheck_ui_static.js` 7 项、`tests/score_distribution.js`；报告与 Excel 新增 `multiplier`、`cooldown_count`、`cooldown_sec`。
- **状态**：已采纳（补充 D-018，不替换脑电计分公式）。

### D-022 本地 SQLite 作为多档案权威存储（v1.8.1）

- **背景**：v1.7 之前的成长/校准/报告分散在 `localStorage`、内存 Session 和 `outputs/sessions`，无法稳定支持一个家庭多个孩子，也不能可靠备份/迁移。
- **决策**：以系统文档目录 `专注小蛙/profiles.db` 为权威存储，`users` 下按 `user_id` 隔离校准、游戏/逐轮、钱包、装扮、成就、设置；Session 创建时固定用户，后端 `finish/calibrate/manual/stream/monitor/report/export` 校验归属；钱包以 `session_id` 幂等；完成 Session 900 s 后回收内存但保留数据库报告；旧 JSON/LocalStorage 只在用户明确目标后迁移；浏览器 `bf-*` 仅作当前档案缓存。数据目录支持迁移/备份/恢复，SQLite 未加密需明确说明。
- **代价**：需要维护 Schema/事务；同 OS 账户可读数据库；无静态加密；单机单进程为主；离页同步失败时最后一次浏览器缓存可能丢失。
- **证据**：`app/storage.py`、`app/accounts.py`、`app/server.py`、`web/profiles.html`、`web/settings.html`、`tests/selfcheck_v181.py`、`docs/DEV-REPORT-v1.8.1.md`。
- **状态**：已采纳；macOS 实机通过，Windows 实机未验收。

### D-023 每日校准与长期参考双轨（v1.8.2）

- **背景**：每日状态会变化，但长期指标不应被每日重新归一化抹去；同时正式游戏不能偷偷重算。
- **决策**：每日首次真实硬件游戏前完成“自然观察 30s + 教学 30s”（有效帧计时、P15/P85、等权合并）；同日同设备 4h 内复用。首个有效硬件校准自动建长期参考 v1，每日不覆盖；显式版本化建 v2+。服务端在创建游戏 Session 时锁定量程/参考快照，游戏内 `/calibrate` 409。`S_reference` 只做后台趋势，不参与游戏计分。测试/回放/手动/心率不建真实参考。
- **代价**：阶段/设备/日期规则增加状态复杂度；参考 v1 不是临床稳定能力；教学为校准页轻量蓄力交互，不是完整 3D 游戏。
- **证据**：`app/calibration.py`、`app/storage.py`、`app/server.py`、`web/calibrate.html`、`tests/selfcheck_v182.py`、`docs/DEV-REPORT-v1.8.2.md`。
- **状态**：已采纳；模拟/开发模式验证，真机/儿童未验收。

### D-024 个体自适应难度只调黄色区域起点（v1.8.3）

- **背景**：部分儿童蓄力过慢、部分过快；需要个体适配，但不能把难度变化混入脑电分数或长期基线。
- **决策**：
  - 只调整黄色区域起点范围；默认 1.00，范围 0.60–1.20。
  - 局内锁定，局间调整；不改实时表现、不改计分公式、不改区域宽度。
  - 净蓄力 `eval_sec` 排除冷却/断流/暂停/子弹时间/跳跃动画；`charge_sec` 保持原计分口径。
  - 未完成轮次单独记录；无有效蓄力先查信号/校准，不通过不断缩短区域制造反馈。
  - 中位 >12s 连续 2 局降低 10%；<4s + 点击≥85% + ≥3 次完整进入连续 3 局提高 10%；4–12s 保持。
  - 信号/活动不足、点击/乱点瓶颈不调整；真实硬件、非 demo、正式 game 才写档案。
- **自主边界**：0.60 时名义 14.4% 低于起始能量 15%，实际下界抬至 17% 并保留名义值审计；这是保证区域完整/可蓄力的技术决策。
- **证据**：`app/difficulty.py`、`app/storage.py`、`web/assets/focus-round.js`、`web/game.html`、`web/dev.html`、`tests/selfcheck_v183.py`、`tests/selfcheck_v183_round.js`。

### D-026 诊断只解释，不自动改游戏参数

- **背景**：低速场景在最低难度 0.60 仍可能超过 12s 目标；若诊断直接改蓄力速度，会破坏 v1.8.3 的机制边界。
- **决策**：9 类诊断只读现有状态机并附证据；最低难度仍难作为独立状态；不自动改阈值、速度、点击窗口或最低难度。
- **代价**：问题会被记录但不会自动消失，需要后续版本单独设计。
- **证据**：`app/diagnostics.py`；`tests/selfcheck_v184.py`；低速模拟。
- **状态**：已采纳。

### D-027 标准评估复用 Session 链路，独立记录与奖励隔离

- **背景**：评估必须固定参数，又不能污染个人难度/积分/校准。
- **决策**：`purpose=assessment` 复用 Session/报告，但固定 1.00、固定 seed、写独立 `assessments` 表；完成时不发积分、不写难度、不推进连续计数。
- **代价**：评估与游戏共享信号/算法代码，必须持续测试隔离；模拟源不能作为正式纵向结果。
- **证据**：`app/server.py`、`app/storage.py`、`tests/selfcheck_v184.py`；评估 API 返回 `assessment_isolated`。
- **状态**：已采纳。

### D-028 导出先写本地 reports，再交给浏览器下载

- **背景**：诊断包含逐轮与校准信息，不应自动上传；同时用户需要拿到文件。
- **决策**：服务端写 `reports/`，API 返回文件名/路径/内容；浏览器通过 Blob 下载同一内容；默认脱敏昵称与高频原始波形。
- **代价**：导出文件仍在本地且未加密；大报告可能较大。
- **证据**：`app/dev_export.py`、`/api/dev/diagnostics/{sid}/export`；JSON/CSV 测试。
- **状态**：已采纳。
