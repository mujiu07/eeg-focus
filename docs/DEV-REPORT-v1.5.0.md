## 2. 核心机制修改前后对比

| 维度 | 修改前 | 修改后 |
|---|---|---|
| 单跳得分 | 主动 +2 / 自动 +1 | 进入金色区域时锁定 20–100 的潜在得分，点击兑现、错过 0 |
| 得分区分度 | 最高/最低 2:1 | 模拟 90 s：稳定高分 504、间歇 306、稳定低分 74（同一套点击策略） |
| 蓄力衰减 | 分心只停不倒退 | 1.5 s 宽容期内保持；超过后按 `V_ref×30%` 缓慢衰减至 0 |
| 负增益 | 滞回 38–42 区间可能算出负增益 | `max(0, speed)`，并钳制能量 0–100 |
| 金色区域 | 进入后错过会顺延生成新区间 | 每轮只生成一次；错过不补、不重掷 |
| 点击窗口 | 蓄力越快，窗口越短 | 固定 2.5 s 子弹时间，所有玩家一致 |
| 子弹时间移动 | 无 | `slowSpeed = 6% / 2.5s = 2.4%/s` |
| 自动得分 | 蓄满 100 自动 +1 | 删除自动得分；普通跳跃只维持流程 |
| 防刷分 | 仅靠动画状态 | 引擎 `settled` + 相位 + 动画状态三重保护 |
| 信号异常 | 伪迹窗保持上一帧继续玩 | 不可用异常窗冻结蓄力/衰减/计时/子弹时间；可修复眨眼仍出分 |
| 积分经济 | 表现分直接当积分（1–2/跳） | 表现分与积分分离：`max(1, floor(表现分/30))` |
| 数据记录 | 起跳时间与 timed/auto | 逐轮蓄力用时、区域位置、T_ref、潜在/实际分、反应时、均值、达标率、衰减、异常时长、提前点击 |

## 3. 实际采用的计分公式

```
D = zone.lo − startEnergy            # 本轮起点到金色区域起点的距离
V_ref = (65 − 42) × 0.16 = 3.68 %/s  # 基准蓄力速度
T_ref = D / V_ref
S = round(20 + 80 × T_ref / (T + T_ref))
```

- `T`：本轮从开始到首次进入金色区域的有效用时，包含正常蓄力、等待、宽容期与衰减；不含信号异常、暂停、子弹时间、跳跃动画。
- `S` 在进入金色区域的瞬间锁定，之后不因点击反应或脑电变化重算。
- 边界：`T=0 → 100`；`T→∞ → 20`；`D=0`、`T` 非法、除零回落到 20；最终 clamp `[20,100]`。
- 随机位置公平性：相同平均蓄力速度下 `T ∝ D`，`T_ref ∝ D`，因此 S 与随机起点近似无关。测试中 `lo=26/45` 均为 60 分。
- 实际可达上限受分数上限 100 与 V_ref 约束，约 77 分；20–100 为公式钳制范围。

模拟结果（90 s，奇数轮点击、偶数轮故意错过）：

| 画像 | 得分 | 成功 | 错过 | 完成轮次 |
|---|---:|---:|---:|---:|
| 稳定高分（85） | 504 | 7 | 7 | 14 |
| 间歇性高分（4 s 85 / 4 s 35） | 306 | 5 | 4 | 8 |
| 快速波动（50–90，1.5 s 周期） | 385 | 6 | 5 | 11 |
| 稳定低分（48） | 74 | 2 | 2 | 4 |
| 稳定高分 + 12 s 断流 | 504 | 7 | 6 | 12 |

> 以上为**模拟脑电**，不是真机数据；仅用于验证机制方向与边界。

## 5. 游戏状态转换

```
CHARGING
  │ energy 首次 >= zone.lo
  ▼
BULLET_TIME（锁定 S，2.5 s 慢速穿过）
  │ 点击                         │ 2.5 s 未点击
  ▼                              ▼
JUMP_SUCCESS（+S）          JUMP_MISSED（+0）
  │ 跳跃 0.55 s → 水花/上浮 → 视角归位
  └──────────────┬───────────────┘
                 ▼
              RESET（写入本轮记录、生成新区域、energy=15）
                 │
                 ▼
              CHARGING
```

- `PAUSED` 为覆盖态：信号异常/主动暂停时冻结能量、衰减、单轮计时、子弹时间；恢复后从冻结处继续，不重算。
- `RESET` 只在 `pendingSettle` 与 `settling` 都结束后执行，动画时间不进入下一轮 `T`。
- 防重复：引擎 `settled` 标志 + 相位判断 + `state.jumping/settling/pendingSettle` 判断；长按/按键重复在输入层过滤。

## 7. 积分经济处理

- **表现分**：报告与结算卡片显示，单跳 20–100。
- **商城积分**：`max(1, floor(本局表现分 / 30))`，有得分时至少 1 分；单跳约 1–3 分，接近旧版 1–2 分的节奏。
- **历史数据**：`bf-wallet` 结构不变，旧余额保留；不迁移、不清空。
- **成就**：全部按游玩时长/打卡解锁，未使用得分阈值，不受影响。
- **旧会话**：`score` 字段仍是旧口径；报告按字段回退，不做历史重算。
- **开发者模式**：仍不计积分。

## 9. 尚未验证的问题

1. **真机测试未完成**：没有 Xmuse 实机/儿童受试者，所有结果均来自模拟脑电与手动会话；不能称为真机验证。
2. **极低专注下的子弹速度**：`slowSpeed=2.4%/s` 低于基准 3.68%/s，但刚过 42–48 分时玩家正常蓄力可能更慢；该区间已接近得分下限，真机若反馈“子弹时间反而变快”，优先调 `zoneWidth`、`bulletTimeSec` 或蓄力增益。
3. **浏览器视觉/交互 E2E 未自动化**：发光、减速、青蛙姿态、背景压暗已做静态与语法检查，未在真实浏览器逐项截图回归；建议在低端平板与 60 Hz/30 Hz 掉帧场景各看 1 局。
4. **主动暂停无入口**：核心模块支持 `paused`，儿童端目前只有信号异常触发冻结；若后续加暂停按钮，计时排除逻辑已就绪。
5. **真实积分节奏**：30:1 是按旧 1–2 分/跳估算的保守值，未做多家庭长期留存验证；可在 `CONFIG.pointsDivisor` 一处调整。
6. **数据研究价值**：逐轮数据可用于平衡分析，但样本量、设备差异与儿童佩戴质量都未验证，不能据此做临床判断。

## 10. 自主决策说明

| 决策 | 理由 |
|---|---|
| V_ref 取分数 65（3.68%/s） | 在现有 `(score−42)×0.16` 增益下，65 分是“稳定专注”的中间工作点；使 20–100 公式在实际游戏中产生约 29–77 的可用区间 |
| 金色区域宽度 6%、位置 24–55% | 保证 `6/2.5=2.4%/s` 低于基准 3.68%/s；随机范围对应约 2.4–10.9 s 等待，避免干等 |
| 首轮 22–34% | 沿用原“首轮更早”的教学节奏，降低首次体验的等待 |
| 30:1 + 有得分至少 1 分 | 比 20:1 更接近旧经济（旧版 1–2 分/跳），避免商城 5–18 分被快速买空 |
| 把伪迹窗改为冻结 | 需求明确要求“已识别异常数据”冻结；后端只有 `usable=false` 才判无效，可修复眨眼仍正常出分，兼顾体验 |
| RESET 隐式、PAUSED 覆盖态 | 复用现有动画状态机，避免为命名而重构；行为与需求状态图一致 |
| 表现分与积分分离 | 保留 20–100 的区分度，同时不冲垮旧商城定价与历史余额 |
| 报告展示平均潜在得分而非公式 | 家长可读，不把公式/倒计时塞进儿童端 |
