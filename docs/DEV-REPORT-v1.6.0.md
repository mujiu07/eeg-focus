# 开发报告：核心玩法二次优化（v1.6.0）

> 日期：2026-11-27
> 范围：在 v1.5.0 基础上增加点击时机折损、无效点击冷却与儿童端低负荷展示
> 原则：不替换脑电计分公式；点击时机最多影响 10%；无效点击只冷却、不扣分；不新增地图/角色/模式/排行榜/连击。

---

## 1. 实际修改内容

### 1.1 金色区域内计分

- 保留 v1.5.0 的脑电基础分公式：`B = round(20 + 80 × T_ref / (T + T_ref))`，`T_ref = D / V_ref`。
- 进入金色区域时仍只锁定一次 `B`；子弹时间、信号波动、点击反应都不再改 `B`。
- 新增点击时机倍率：

```
M(t) = 1                                  0 ≤ t ≤ G
M(t) = 1 − R × (t − G) / (W − G)          G < t < W
M(t) = 0                                  t ≥ W

S = round(B × M(t))
G = 0.6 s, W = 2.5 s, R = 0.10
```

- 前 0.6 s 点击拿满基础分；之后线性下降；窗口结束前最低约 90%；超过 2.5 s 为 0。
- 例：`B=76` → 0.2/0.6 s 得 76，1.0 s 得 74，1.5 s 得 72，2.0 s 得 70，2.4 s 得 69，超时 0。

### 1.2 无效点击冷却

- 正常蓄力阶段点击：立即触发 **0.5 s** 冷却。
- 冷却期间：
  - 暂停能量增长；
  - 不额外执行衰减；
  - 本轮计时继续累计；
  - 不扣分、不清空蓄力、不产生跳跃。
- 冷却中再次点击不叠加、不延长；冷却结束后的独立无效点击可重新触发。
- 冷却期间能量不能进入金色区域。
- 动画、暂停、结算期间点击直接忽略，不产生奖励或惩罚。
- 仅响应新的按下事件；键盘 `event.repeat` 被忽略；长按不会自动起跳。
- 首次无效点击显示一次低刺激提示“等到黄色区域再跳哦”，约 1.6 s 后消失，不反复弹出。

### 1.3 儿童端低负荷展示

- 正常游戏隐藏：实时脑电分、实时蓄力百分比、BPM、信号质量、潜在得分、百分制文案。
- 正常游戏保留：青蛙、荷叶、蓄力条、金色区域、本局累计积分、剩余时间、专注状态灯、音效开关。
- 成功跳跃：青蛙附近显示柔和 “+N” 约 **1.0 s**，同步更新本局积分；不显示“完美 +N”。
- 错过：普通跳跃、0 分，不显示 “+0”、不显示失败/注意力不足、不播庆祝音效。
- 子弹时间：金色区域左深右浅渐变 + 轻微发光；不显示锁定分、倍率、倒计时或新操作目标。
- 开发者模式（`?demo=1` / `?test=manual|replay`）保留全部实时数字，后台数据记录不变。

### 1.4 数据与经济

- 逐轮新增：`multiplier`（点击倍率）、`cooldown_count`、`cooldown_sec`。
- `potential` 明确为**脑电基础分 B**；`awarded` 为**实际积分 S**。
- 会话级新增：`cooldown_count`、`cooldown_sec`。
- 报告新增：金色时机命中率、每轮平均脑电基础分、每轮平均实际得分、提前点击与冷却次数。
- Excel「每轮数据」新增：点击倍率、冷却次数、冷却时长；“潜在得分”列改名为“脑电基础得分”。
- 积分经济继续分离：`商城积分 = max(1, floor(本局累计积分 / 30))`（有得分时）；结算卡片显示“商城积分 +N”，与 HUD 的“本局积分”区分；历史钱包、已购装扮、历史会话、成就阈值不清空、不迁移。

## 3. 新旧机制对比

| 维度 | v1.5.0 | v1.6.0 |
|---|---|---|
| 金色区域内得分 | 任意位置点击都拿满 B | 前 0.6 s 拿满 B；之后线性下降，最多折损 10%；超时 0 |
| 点击时机作用 | 无 | `S = round(B × M(t))`，行为响应最多影响 10% |
| 非金区点击 | 只计数，无成本 | 0.5 s 冷却：暂停增长、计时继续、不衰减、不扣分、不清空 |
| 冷却叠加 | 无 | 冷却中重复点击不叠加、不延长；结束后可重新触发 |
| 冷却进入金区 | 无 | 冷却期间禁止进入；结束后再判断 |
| 儿童端实时数字 | 显示信号分/蓄力百分比/BPM/质量 | 默认全部隐藏；仅开发者模式显示 |
| 成功反馈 | “完美 +N” | 青蛙附近 “+N”，约 1.0 s |
| 错过反馈 | 普通跳跃、0 分 | 不变；额外确认不显示 +0/失败 |
| 金色区域视觉 | 纯色 + 发光 | 左深右浅渐变 + 发光 |
| 逐轮数据 | potential/awarded/early_taps… | 增加 multiplier/cooldown_count/cooldown_sec |
| 报告口径 | 游戏表现分（易被读成百分制） | 本局游戏积分 + 每轮基础/实际分 + 命中率 |
| 脑电计分公式 | `B = round(20+80×T_ref/(T+T_ref))` | **保留不变** |

### 公平性与边界

- 相同 65 分蓄力速度下，区域起点 24–55% 的基础分均为 **60**，极差 **0 分**。
- 稳定 42 分在 90 s 内无法蓄力（0 轮）；45 分约 2 轮；100 分约 18 轮；极高/极低边界无负分、无越界。
- 有效基础分范围约 **29–77**；85→100（脑电 +15 分）只带来 5 分基础分提升，高分段存在原公式的自然压缩。

**结论**：区分度足够支撑玩法（低/中/高/极高与间歇画像可分），但高分段压缩明显。本轮**不替换公式、不乘倍数**；若后续要提高高分段区分度，先做 `vRefScore`/曲线参数对比实验，再决定是否调整。

## 7. 未解决的问题

1. **真机测试未完成**：没有 Xmuse 实机与儿童受试者；所有分布、冷却与按钮操作均为模拟脑电/无头浏览器。正常儿童模式需要硬件校准，本地用开发者模式 + DOM 模拟 clean HUD 验证；该分支由静态检查覆盖，但未做真机儿童端 E2E。
2. **高分段压缩**：有效基础分约 29–77；85→100 只有 5 分提升。已给出数据与建议，但未改公式。
3. **低专注下的子弹速度**：刚过 42–48 分时正常蓄力可能慢于 2.4%/s，子弹时间不一定更慢；仍需真机反馈。
4. **主动暂停无入口**：核心模块支持 `paused`，儿童端目前只有信号异常触发冻结。
5. **导出依赖**：`.venv` 缺 `openpyxl/reportlab/python-docx`，PDF/Excel/Word 接口在本机不可用；需按 `requirements.txt` 安装后验收。
6. **经济上限**：模拟 90 s 全成功约 1386 分 → 46 商城积分；单次成功约 2–3 积分，仍接近旧版，但高成功率玩家的总积分会偏高，需要真机/家庭数据观察。

## 8. 自主技术决策

| 决策 | 理由 |
|---|---|
| 保留 `B` 公式，只新增 `M(t)` | 脑电仍是主导；点击时机最多影响 10%，符合任务要求 |
| 冷却放在 `CHARGING` 子状态 | 不新增 `phase`，避免动画/异常/结算状态分叉 |
| 冷却期间继续累计 `T` | 让提前点击通过“用时增加”间接降低基础分，而不是直接扣分 |
| 冷却期间不衰减 | 冷却不是走神，不叠加惩罚；但 `belowSec` 仍累计，冷却结束后按真实低专注处理 |
| 冷却中重复点击不延长 | 防止高频点击把冷却变成持续惩罚 |
| 正常模式隐藏 BPM/质量 | 属于“其他不必要的实时统计”，降低儿童认知负荷；开发者模式保留 |
| 成功反馈只显示 “+N” | 取消“完美”评价与百分制联想，只表达游戏奖励 |
| 金色区域渐变左深右浅 | 不增加文字/按钮，用视觉暗示“越早越好” |
| 报告保留基础分/实际分两列 | 区分脑电反馈表现与行为操作表现，便于后续平衡分析 |
| 不调整 `vRefScore`/公式 | 高分段压缩已记录；任务要求不擅自替换核心公式 |
