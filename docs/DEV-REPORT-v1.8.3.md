# 开发报告：v1.8.3 个体自适应难度

> 日期：2026-11-27
> 基准：v1.8.2（`ccec075`）
> 性质：儿童脑电游戏机制的工程原型，不是临床训练或注意力诊断研究。

## 1. 目标与边界

v1.8.3 在现有每日校准、双基线、SQLite 多用户档案和正式游戏 Session 上，增加**个体自适应游戏难度**。

唯一允许自动调整的游戏参数是：

- 黄色区域起始位置的随机生成范围。

明确不修改：

- EEG 特征、每日校准、长期参考基线；
- 脑电映射 `x -> 20–80`；
- 蓄力阈值、蓄力速度、衰减、宽容期、子弹时间；
- 黄色区域宽度、点击折损、基础积分和商城换算。

设计原则：

1. **适配游戏难度，不改脑电分数。**
2. **局内固定，局间调整。**
3. **连续有效胜出才调整，不因一局波动或误点降难度。**
4. **真实硬件、测试源、不同用户严格隔离。**
5. **历史 Session、校准、积分和装扮不因难度调整而改写。**

## 2. 与 v1.8.2 实际代码的核对

核对文件：[`web/assets/focus-round.js`](../web/assets/focus-round.js)

- 实际常规黄色区域起点配置为 **24–55%**，宽度 **6%**。
- 每轮在范围内随机采样一次；区域末端限制为不高于 **92%**。
- 每轮从 `startEnergy=15%` 开始；当前引擎实际使用常规范围，代码中存在的 first-round 字段不会改变正式游戏的标准范围。
- 计分仍使用 `chargeSec`（包含等待、宽容、衰减和无效点击冷却）。
- 单轮内部新增 `evalSec`，作为难度评估的净用时；不替换计分的 `chargeSec`。

### 2.1 低难度下界的自主决策

用户给出的系数表在 `0.60` 时名义下界为：

```text
24 × 0.60 = 14.4%
```

但每轮起始能量是 `15%`，14.4% 会导致“开局已经在区域内”，距离为零。为避免生成零距离/负距离，v1.8.3 对实际起点增加安全下界：

```text
start_energy + min_zone_distance = 15 + 2 = 17%
```

因此：

- `zone_low_min/max` 是实际使用的范围；
- `nominal_zone_min` 保留名义值 14.4；
- `zone_range_clamped=true` 标记下界被安全约束；
- 宽度仍固定 6%；末端仍不超过 92%。

这是“只调整黄色区域起点”范围内的安全实现，不修改起始能量或其他规则。

## 3. 难度模型

配置集中在 [`app/difficulty.py`](../app/difficulty.py)：

| 参数 | 值 |
|---|---:|
| 默认 `difficulty_factor` | 1.00 |
| 最低 / 最高 | 0.60 / 1.20 |
| 降低倍率 | 0.90 |
| 提高倍率 | 1.10 |
| 适宜净蓄力 | 4–12 s |
| 降低连续局数 | 2 |
| 提高连续局数 | 3 |
| 提高点击成功率 | ≥85% |
| 最低信号有效比例 | 70% |
| 降低所需最低活动 | 45 s |
| 提高所需完整轮次 | 3 |
| 局内调整 | 禁止 |

实际起点：

```text
nominal_min = 24 × factor
nominal_max = 55 × factor
zone_low_min = max(nominal_min, 17)
zone_low_max = min(max(nominal_max, zone_low_min), 86)
zone_width = 6
```

例如：

| factor | 名义范围 | 实际使用范围 |
|---:|---:|---:|
| 0.60 | 14.4–33.0% | 17.0–33.0% |
| 0.80 | 19.2–44.0% | 19.2–44.0% |
| 1.00 | 24.0–55.0% | 24.0–55.0% |
| 1.10 | 26.4–60.5% | 26.4–60.5% |
| 1.20 | 28.8–66.0% | 28.8–66.0% |

`86 = 92 - 6`，保证区域完整且不越界。

## 4. 局内固定与 Session 快照

创建硬件正式游戏 Session 时，服务端锁定并向游戏返回：

- 当日校准 id/参数；
- 长期参考版本；
- `difficulty_factor`；
- `zone_low_min/max`、`zone_width`、`zone_hi_max`、`start_energy`；
- 难度策略版本 `adaptive_v1`；
- 游戏参数版本 `v1.8.3`。

游戏页收到响应后重新建立 `RoundEngine`，整个 Session 不再读取个人档变化。每次跳跃仍由本局固定的随机范围采样。

正式游戏进行中：

- 不依据实时表现修改范围；
- 调用 `/api/session/{sid}/calibrate` 仍返回 409；
- 手动改档不会回溯当前 Session。

## 5. 指标计算

### 5.1 计分时间与评估时间分离

`RoundEngine` 同时记录：

- `charge_sec`：现有计分时间，含等待、宽容、衰减和无效点击冷却；
- `eval_sec`：净蓄力评估时间，仅累计 `CHARGING` 的有效帧，排除：
  - 断流/`signalOk=false`；
  - 主动暂停；
  - 子弹时间；
  - 跳跃动画；
  - 无效点击冷却。

等待、宽容期和衰减仍计入 `eval_sec`，因为没有有效信号时不会累计。

### 5.2 未完成轮次

上局结束若仍在 CHARGING 或 BULLET_TIME，前端上报 `incomplete_round`：

- 当前持续秒数；
- `eval_sec`；
- 当前能量、起始能量、能量增长；
- 区域范围；
- 是否已进入区域；
- `ended_reason=time_up`。

它只代表已观察到的时间下限，不进入完整轮次中位数，不能被当作完整蓄力。

### 5.3 主要指标

| 指标 | 定义 |
|---|---|
| 中位净蓄力 | 已进入区域轮次的 `eval_sec` 中位数；未进入仅保留观察下限 |
| 进入次数 | `potential != null` 的完整轮次 + 已进入的未完成轮次 |
| 成功点击率 | 成功 / 进入次数 |
| 错过点击 | 进入后未成功 |
| 提前点击 | `early_taps` |
| 冷却 | `cooldown_sec` 及活动占比 |
| 信号比例 | 服务端 `n_valid_frames / n_frames` |
| 有效活动 | 所有轮次及未完成轮次的 `eval_sec` 之和 |
| 未完成轮次 | 当前未结束的一轮；0/1 |
| 长时间无法进入 | 未进入且净观察 ≥12 s |

评估门槛：

- `planned_sec >= 60`；
- `active_sec >= 45`；
- `signal_ratio >= 70%`；
- 真实硬件、非 demo、正式 game；
- 提高难度还需≥3次进入且点击率≥85%。

## 6. 局间判定

`classify` 优先级：

1. 非硬件/测试源 → `INSUFFICIENT_DATA`，不写档案；
2. 信号不足 → `SIGNAL_OR_CALIBRATION_CHECK`；
3. 计划时长不足 → `INSUFFICIENT_DATA`；
4. 高频提前点击 + 冷却占比高 → `BEHAVIOR_BOTTLENECK`；
5. 未进入且有能量增长但活动不足 → `INSUFFICIENT_DATA`；
6. 未进入、无有效能量增长 → `SIGNAL_OR_CALIBRATION_CHECK`；
7. 未进入、长时间且有能量增长 → `TOO_HARD`；
8. 点击率低且净蓄力不慢 → `BEHAVIOR_BOTTLENECK`；
9. 中位 >12 s → `TOO_HARD`；
10. 中位 <4 s、点击率≥85%、进入≥3 → `TOO_EASY`；
11. 4–12 s → `SUITABLE`。

连续计数：

- `TOO_HARD` 连续 2 局 → `factor = max(0.60, factor × 0.90)`；
- `TOO_EASY` 连续 3 局 → `factor = min(1.20, factor × 1.10)`；
- 适宜、行为瓶颈 → 清零；
- 无效/信号检查不推进；
- 调整后清零；
- 达到上下限不越界；
- 重新校准、换设备、修改策略、手动控制 → 清空连续计数，个人系数可继承。

点击低、但蓄力正常时只记录 `BEHAVIOR_BOTTLENECK`，不降低蓄力难度；本阶段不调整子弹时间/点击窗口。

## 8. API

- 创建 Session 响应新增 `difficulty` 快照。
- `GET /api/profiles/{user_id}/difficulty`：难度档、最近指标、连续计数、最近历史。
- `POST /api/profiles/{user_id}/difficulty`：
  - `auto_enabled`：开关自动适配；
  - `manual_lock`：手动锁定；
  - `factor`：手动设置并锁定（0.60–1.20）；
  - `reset`：恢复 1.00。
- 结束 Session 响应新增 `difficulty` 判定；只有报告保存成功后才处理。
- 同一 `session_id` 再次结束：不会再次调整，返回 duplicate 信息。

## 10. 计分与经济兼容

计分代码未改：

```text
T_ref = D / V_ref
B = round(20 + 80 × T_ref / (T + T_ref))
S = round(B × M)
```

其中 `D` 使用当前实际生成的区域距离。相同稳定蓄力速度下，`T` 随 `D` 变化，单次基础分近似保持不变。点击折损、无效点击冷却、区域宽度、商城换算均未改。

但难度降低会增加单位时间内跳跃次数，因此累计积分和商城货币可能上升。**不同难度的累计积分不能作为长期脑电表现改善证据。**

## 13. 尚未解决/限制

- 没有真实 Xmuse 真机和儿童受试者；本报告所有结果均为工程模拟/开发模式验证，不能宣称训练效果。
- 真实儿童可能会把“更小的黄色区域”当作新的游戏规则；本阶段没有做真实可用性测试。
- `eval_sec` 由前端单轮状态机上报，服务端只校验 Session/来源/时长等边界；若未来需要抗篡改，应增加服务端逐帧事件重算。
- 低系数安全下界 17% 与用户给出的 14.4% 名义值不同，已在差异中显式记录。
- 没有自动点击窗口、子弹时间、蓄力速度适配；点击瓶颈只记录不处理。
- 未实现 v1.8.4 完整个体适配面板、跨设备/云同步、桌面安装包和完整成长报告。
- SQLite 未做静态加密；依赖本机账户与磁盘加密。
- 未验证 Windows 实机。

## 14. 自主技术决策

1. **安全下界**：为避免 0.60 系数下 `14.4 < startEnergy 15` 的开局即进入区域，实际下界抬至 17%，并保留名义值供审计。
2. **不改计分时间**：新增 `eval_sec` 而不是修改 `charge_sec`，保证计分公式和冷却惩罚完全兼容。
3. **未完成轮次独立**：不把未完成轮次混入中位数，只记录观察下限和能量增长，避免“整局没进入”被空中位数忽略。
4. **服务端判定**：难度调整只在 Session 成功保存后执行，并用 `session_id` 唯一索引保证幂等。
5. **来源隔离**：只有 `source.name=hardware`、非 demo、正式 game 才写真实难度档案；测试源可运行策略但不落真实档案。
6. **手动优先**：活动 Session 期间改档不回溯旧快照；结束旧 Session 时若发现个人档已改，不覆盖新设置。
