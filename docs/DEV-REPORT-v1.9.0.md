# 专注小蛙 v1.9.0 开发报告：个人成长中心与历史报告

> 版本：v1.9.0（2026-11-27）
> 基线：v1.8.4 `7e44a28`
> 范围：儿童成长日记、家长成长中心、标准评估长期趋势、历史游戏详情、个人报告导出
> 定位：本地运行的游戏与任务记录工具，不是医疗器械，不输出临床注意力结论

## 1. 交付摘要

v1.9.0 在不改动 Schema 4 的前提下，从现有 SQLite 的 `users/sessions/rounds/calibrations/reference_baselines/assessments/inventories/achievements` 读取数据，新增：

- 儿童“小蛙成长日记”；
- 家长“家长成长中心”；
- 任意已保存正式游戏的历史详情；
- 固定条件标准评估的分段纵向趋势；
- 个人报告 PDF / Excel / JSON / CSV；
- 首页、设置、成长日记、家长中心与历史详情之间的导航整合。

**没有新增游戏玩法、脑电算法、校准公式、计分机制或云端服务；没有执行数据库迁移，继续使用 Schema 4。**

## 2. 数据来源与统计口径

### 2.1 记录分类

| 分类 | 判定 | 是否进入儿童日记 | 是否进入家长正式游戏统计 | 是否进入真实 EEG 趋势 |
|---|---|---:|---:|---:|
| 正式游戏 | `purpose=game`、`demo=0`、来源 `hardware` 或 `heart` | 是 | 是 | 仅真实硬件且有有效帧 |
| 心率正式游戏 | 来源 `heart` | 是 | 是（无 EEG，不进入脑电趋势） | 否 |
| 校准教学 | `calibrations` 表 / 校准 Session | 否 | 单独计数 | 否 |
| 标准评估 | `purpose=assessment` 且 `assessment.simulation=0` | 否 | 单独计数 | 是，且需满足条件 |
| 模拟标准评估 | `assessment.simulation=1` | 否 | 单独计数 | 否 |
| 模拟试玩 | `demo=1` 或 `manual` 游戏 | 否 | 单独计数 | 否 |
| EDF 回放 | 来源 `replay` 且非正式评估 | 否 | 单独计数 | 否 |

团队选择把 `replay/manual` 与真实硬件分开，即使旧测试报告可能把回放 Session 写成 `purpose=game`；展示层也不会把测试回放混入真实成长趋势。

### 2.2 指标定义

完整定义也通过 API 的 `definitions` 字段返回，并在家长页折叠显示：

| 指标 | 分子 / 口径 | 分母 / 缺失处理 |
|---|---|---|
| 累计使用天数 | 正式游戏、真实评估、有效校准所在的本地日期去重 | 无记录显示 0，不伪造日期 |
| 正式游戏次数 | 正式游戏 Session 数 | 不含模拟、回放、评估 |
| 实际游戏时长 | 正式游戏 `played_sec` 之和 | 缺字段保留 `null`，不以 0 代替 |
| 有效信号采集时长 | 每局 `played_sec × 有效帧比例` 后求和 | 仅硬件且存在帧统计的局；无 EEG 局不计 |
| 成功跳跃 | 完整轮次 `success` 数之和 | 无有效轮次显示“数据不足” |
| 黄色区域进入次数 | 完整轮次 + 有 `entered` 的未完成轮次 | 与成功/失败分母分开 |
| 点击成功率 | 成功跳跃 ÷（成功跳跃 + 未成功完成跳跃） | 分母为 0 显示“数据不足”；提前点击不塞入分母 |
| 点击反应时间中位数 | 仅成功且 `reaction_sec > 0` 的轮次 | 无有效记录显示“数据不足” |
| 净蓄力用时中位数 | 仅完整轮次的 `eval_sec` 中位数 | 未完成轮次单列，不混入；缺失不退回 `charge_sec` |
| 有效信号比例 | 有效帧 ÷ 总帧（仅同时有帧统计的正式硬件局） | 不把“无帧统计”当成 0；低于 85% 标记低质量 |
| 当前难度 | 个人难度档案当前 factor | 没有正式游戏/评估时显示“数据不足”，不展示默认 1.00 冒充观测值 |
| S_reference | 标准评估报告 `reference_score_mean` | 长期参考映射后的任务指标 |
| 映射前输出 | 标准评估报告 `focus_mean` | 0–1 原始算法任务输出 |
| 游戏积分 | 正式游戏 `total_score` 之和 | 不是商城余额，不混入评估 |

### 2.3 日期与 Session 回收

- 前端传 `tz_offset_min`（浏览器 `getTimezoneOffset()`，中国为 `-480`）；
- 后端按浏览器本地时区换算日期；
- 正式游戏按 `started_at` 的本地日期筛选；评估按 `ended_at`/`started_at`；
- 预算 7/14/30 天按本地日历日，包含今天；自定义范围闭区间；
- 历史详情通过 `load_report()` 从 SQLite 读取，不依赖内存 `_sessions`；服务端 Session TTL 回收后仍可打开。

## 3. 儿童成长日记

页面：`web/growth.html`，数据：`GET /api/growth/diary`。

展示：

- 累计正式游玩天数、正式游戏时长、成功跳跃、历史游戏积分；
- 最近 7 个本地日历日（有/无记录明确区分）；
- 最近 5 次正式游戏；
- 来自本地 DB `inventories + achievements` 的装扮与成就（静态图标/名称只做展示映射，拥有关系来自 SQLite）；
- 由真实 Session 派生的成长纪念：第一次游戏、累计 100/500 次跳跃、累计 60 分钟、10 次游戏、第一次真实标准评估；
- 无数据时显示友好空状态。

不展示 EEG 分数、实时脑电、复杂趋势图、儿童排行榜；没有连续签到中断惩罚或表现下降负面评价。

## 4. 家长成长中心

页面：`web/parent.html`，数据：`GET /api/growth/report?range=...`。

页面顶层为家长查看确认层；它是使用场景分隔和免责声明，**不是身份认证**，同一本机账户仍可能访问 SQLite。

包含：

1. 日期范围：近 7/14/30 天、全部、自定义；
2. 使用情况：使用天数、正式游戏、实际/有效信号时长、最近使用、分类计数；
3. 游戏行为：成功跳跃、黄区进入、点击成功率、反应中位数、提前点击、净蓄力、有效信号比例、当前难度；
4. 每日游玩日历与每日时长柱状图；
5. 游戏行为趋势（可切换成功率、反应、净蓄力、有效信号）；
6. 长期表现与标准评估、难度阶梯；
7. 历史正式游戏列表，每行可进入 `history.html?id=...`；
8. PDF/Excel/JSON/CSV 导出；
9. 折叠的指标解释、数据质量与隐私边界。

复杂统计和映射前输出默认折叠，符合家长端“核心信息优先”的要求。

## 5. 标准评估长期趋势与可比性

### 5.1 条件键

只有同时满足以下条件的标准评估才进入同一趋势段：

- 同一 `user_id`（API 强制）；
- 同一设备配置 `device_key`；
- 同一 `algorithm_version`；
- 同一 `mapping_version`；
- 同一 `reference_baseline_id` 和参考版本；
- 同一 `protocol_version`；
- 同一 `planned_sec`；
- 同一 `fixed_factor`；
- 同一难度参数版本/策略版本（存在时）。

系统不把“看起来相近”的设备自动声明为兼容；没有显式兼容映射时按不同设备处理并分段。评估 seed 仅记录随机任务序列，不作为条件键；同协议下 seed 不同属于正常随机差异。该规则在报告中明确写出。

### 5.2 质量与模拟

- 评估必须 `status=completed`；
- `simulation=1` 永不进入真实纵向趋势；
- `valid_signal_ratio < 0.85` 只保留在记录列表并标记，不参与趋势；
- 缺少设备/算法/映射/参考/协议字段的记录不参与比较，并返回原因；
- 不足 2 个有效且同条件点时 `trend_available=false`，只列记录，不计算变化；
- 不同条件按时间顺序形成独立 segment，前端分别画线，不跨段连接。

### 5.3 不做什么

- 不用日常游戏累计积分代替长期标准评估；
- 不用每日校准覆盖长期参考；
- 不让标准评估改变个人难度、商城积分或成就；
- 不把脑电与行为合成为单一“综合专注力评分”；
- 不输出“注意力提高 X%”“ADHD 改善”“治疗效果”等医学结论。

## 6. 历史游戏详情

页面：`web/history.html`，数据：`GET /api/growth/sessions/{sid}?include_rounds=true`。

展示：日期、来源、时长、积分、成功跳跃、点击成功率、反应/净蓄力中位数、难度快照、校准状态、参考版本、信号质量、工程诊断摘要；开发者折叠区显示完整逐轮：

`round, success, entered, reaction_sec, charge_sec, eval_sec, early_taps, potential`。

所有请求都校验 `user_id`；跨用户读取返回 403。服务端 Session 被 TTL 回收后仍从 SQLite 报告读取。逐轮数据不包含原始高频 EEG 波形。

## 7. 报告导出

统一由 `growth.build_report()` 生成数据，再由 `growth_export.py` 输出：

- **PDF**：A4，多页，嵌入系统中文字体（macOS 使用 Arial Unicode，找不到时回退 STSong CID）；包含概览、行为、每日、评估、难度、质量、指标说明；
- **Excel**：8 个工作表：概览、每日使用、正式游戏、标准评估、评估趋势、难度变化、指标说明、数据局限；含每日时长柱状图；
- **JSON**：完整结构化报告，含定义、范围、质量、趋势段；
- **CSV**：长表 `section,date,session_id,metric,value,unit,quality,note`，UTF-8 BOM；
- 文件先写入用户数据目录 `reports/`，再交给浏览器下载；使用临时文件 + `os.replace`，写失败不返回成功；
- 文件名支持简体中文；默认不含原始高频 EEG 和不必要的身份信息；
- 空范围返回 409，不生成空白文件。

实测样本：`outputs/v1.9.0/growth-report-example.{pdf,xlsx,json,csv}`。PDF 5 页，中文可提取；Excel 8 表。

## 8. 导航与隔离

首页新增主要功能条：开始游戏、 小蛙装扮、成长日记、家长报告、设置；设置页也提供成长日记/家长报告入口；开发者工作台保留独立入口。没有新增多级页面，原有游戏流程不变。

家长页有使用场景确认层，但它只是界面分隔，不是密码或身份认证；隐私文档明确说明这一点。

## 10. 已知问题与风险

- **没有真实 Xmuse 真机、儿童/家长可用性测试、Windows 实机**；截图和趋势均为虚构 fixture 验证，不能当作临床或真机验收。
- `eval_sec`、逐轮事件仍由前端状态机上报；服务端做边界/一致性校验，但不是防篡改证据。
- 标准评估 90 秒、固定 1.00 是工程协议参数，不是临床常模。
- SQLite 与导出文件尚未静态加密；家长页确认层不是可靠认证。
- 旧 v1.8.1/1.8.2 报告可能没有 `eval_sec`、逐轮字段；系统显示“数据不足”，不伪造。
- 设备“兼容”采用显式/精确条件键；当前没有跨型号兼容映射，因此不同型号会被分段。
- 趋势变化只表示任务指标数值差异，不解释为能力提升或治疗效果。
- 没有云同步、原始高频 EEG 导出、桌面安装包或新游戏难度适配。

## 11. 自主技术决策

| 决策 | 选择 | 代价/边界 |
|---|---|---|
| D-029 不升级 Schema | 复用现有表，新增只读聚合 | 旧报告缺字段时只能显示不足，不能补造 |
| D-030 记录分类 | 用 `purpose/demo/source/simulation` 分类 | `source` 命名必须稳定；回放测试不会进入真实趋势 |
| D-031 精确条件键 | 设备/算法/映射/参考/协议/参数完全一致才同段 | 不做推断式兼容，可能比“宽松比较”切得更细 |
| D-032 seed 不作为条件 | 只作为评估随机序列记录 | 同协议不同 seed 可比较；报告中明确写出 |
| D-033 单一报告数据源 | PDF/Excel/JSON/CSV 均来自 `build_report()` | 导出模块大，需统一测试 |
| D-034 本地临时文件 | 先写 `reports/` 临时文件再原子替换 | 仍需用户自行保护磁盘/文件权限 |
| D-035 家长入口是场景分隔 | 显式确认 + 免责声明 | 不是密码认证，不能防同一账户访问 |

## 12. 后续建议

- 用真实硬件完成 10–15 次标准评估后再评估条件键与实际噪声；
- 增加数据目录/报告文件的 OS 级保护方案，再考虑 v2.0 桌面封装；
- 在真实家长/儿童中验证图表可读性、折叠行为与导出内容；
- 如果引入跨设备兼容声明，必须单独定义设备兼容表和验证流程，不能默认放宽比较。
