# 技术设计：专注判定与蓄力语义

> 面向本仓库维护者的判定链路说明。系统结构、选型、数据模型与完整实测记录见工作区 `docs/Tech Design.md`；本文只收录"专注 → 分数 → 蓄力 → 跳跃"这条链路上容易被误读、且改动风险最高的部分。
> 最后更新：2026-11-23

## 1. 判定链路

每 0.5 s 一帧，链路如下：

1. `sources.next_window()`：2 s 窗（`WINDOW_SEC=2`），步长 `STEP_SEC=0.5`
2. `features.extract()`：带通 0.5–45 Hz + Welch PSD → 每通道 11 维
3. `FocusEngine.update()`：`LogisticRegression.predict_proba` → `EMA_ALPHA=0.35` → `focus ∈ [0,1]`
4. `Session.score_of(focus)`：按校准区间映射为 20–80 动态分
5. `web/game.html`：平滑 → 45/38 分滞回判专注 → 蓄力增长

| 参数 | 值 | 位置 | 作用 |
|---|---|---|---|
| `WINDOW_SEC` | 2 s | `app/features.py` | 单次推理窗口 |
| `STEP_SEC` | 0.5 s | `app/sources.py` | 帧节拍（2 帧/秒） |
| `EMA_ALPHA` | 0.35 | `app/focus_engine.py` | 概率平滑，抑制单窗抖动 |
| 分数映射 | `20 + 60·(focus−low)/(high−low)`，clamp 0–100 | `Session.score_of` | 个人定标，避免绝对阈值 |
| `MIN_SPAN` | 0.10 | `Session.calibrate` | 区间过窄时扩窗，防止噪声被放大成满格 |
| 专注滞回 | 进 45 / 出 38 | `web/game.html` | 阈值附近不反复启停 |
| 蓄力零点 | 42 分 | `web/game.html` | 低于此分不增长 |
| 蓄力增益 | `(scoreSmooth−42)·dt·0.16` | `web/game.html` | 连续增益，越专注越快 |
| 蓄力上限 | 100 | `web/game.html` | 满即起跳（+1） |
| 落地能量 | 15 | `web/game.html` | 下一跳需重新攒 85 点 |
| 断流判定 | 3 s 无有效帧 | `web/game.html` | 暂停蓄力与计时 |

## 2. 分数映射：为什么不能用绝对阈值

历史问题：早期实现直接以 `focus > 0.012` 作为触发条件。0.012 恰是某次 4 s 校准得到的 P50，而不是一个可推广的工作点，导致条件几乎恒真——0.25、0.5 乃至 0.05 都能蓄力，任何微弱信号都会攒满触发跳跃。

当前实现：

- `low/high` 取校准窗的 P10/P90，映射到 20–80 分；
- 区间跨度小于 `MIN_SPAN=0.10` 时，围绕中点扩展窗口，避免"窄区间放大噪声"；
- 校准返回 `range_quality ∈ {ok, stretched, default}`；`stretched/default` 时校准页提示"区分度偏低，建议重做"（只提示，不阻断）。

低基线实测（`q10/q50/q90 = 0.006/0.012/0.021`）扩窗后区间为 `[0, 0.10]`：

| focus | 映射分数 | 是否达到 45 分蓄力线 |
|---|---|---|
| 0.012（基线本身） | 27.2 | 否 |
| 0.021（q90） | 32.6 | 否 |
| 0.042 | 45.2 | 刚好越过 |
| 0.05 | 50.0 | 是 |
| 0.25 / 0.5 | 100（封顶） | 是（远高于个人基线的异常高值） |

结论：基线值本身不再触发；未校准的兜底区间 `[0.35, 0.75]` 下，0.5 也只有 42.5 分。

## 3. 蓄力与冷却语义

- **不进则停，不倒退**：分心时蓄力条只停止增长，不回退（v1.4.0 起）。旧版按 4.2%/s 递减、约 24 秒清空，会让孩子觉得"白练了"；代价改由局内时间承担——不专注就少跳几次。玩家可见文案见 `game.html`：上手卡片"走神的时候进度会停住，不会往回退"，走神提示条"注意力飘走了，蓄力暂停（进度不倒退）"。
- **没有显式冷却计时器**：代码里没有 `cooldownUntil` 这类时间戳或 `COOLDOWN` 状态。防连跳由三段动作状态隐式构成：`jumping.active`（固定 0.55 s）→ `pendingSettle`（等水花散尽、新荷叶浮出水面并回弹稳定）→ `settling`（视角平移回中），三段期间一律不蓄力；落地时 `energy = 15`，下一跳需重新攒 85 点。实际空窗约 1.5–2 s，随特效与距离浮动。
- **取舍**：隐式冷却与动画严格同步，不会出现"动画没结束就能蓄力"或"站好了还要干等"；代价是冷却时长不可单独调、无法在报告里度量。若后续需要可调冷却，应在 `state` 增加 `cooldown` 秒数，每帧 `cooldown = max(0, cooldown - dt)`，并在蓄力条件追加 `cooldown <= 0`；取值应不小于现有空窗下限，否则会改变手感。
- **异常帧不参与判定**：见第 4 节。

## 4. 异常与断流

| 情况 | 当前行为 |
|---|---|
| 单帧被伪迹门控 | `focus = null`、`valid = false`；前端冻结上次分数并标记 stale |
| 采样/推理异常 | `focus = null`、`valid = false`、`meta.error` 带原因，循环继续，不中断游戏 |
| 断流超过 3 s | 暂停蓄力与计时，提示"正在等待信号，计时已暂停" |
| 信号恢复 | 收到有效帧后清除 stale，蓄力与计时恢复 |
| 校准窗口无帧 | 返回 500「校准期间未采集到足够信号帧」 |

> 注：工作区 `docs/Tech Design.md` 第 5 节曾记录"采样/推理异常 → `raw=focus=0.5`"，那是 2026-10 的旧实现；当前代码已改为 `focus=null`，不会向判定链注入伪值。

## 6. 已知取舍

- **隐式冷却**：可调性差，但不会与动画错位（见第 3 节）。
- **分心不回退**：体验优先，代价是"专注时长"语义略弱。
- **低基线的相对性**：基线 0.012 的受试者在 0.05 即得 50 分，这是"相对个人"的正常结果；若校准区分度不足，应通过 `range_quality` 提示重做，而不是放宽判定。
