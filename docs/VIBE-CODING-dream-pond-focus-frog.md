## 1. 从想法到原型

### 1.1 起点

- 课程要求做真实项目；选题来自"ADHD 儿童注意力训练"这一真实痛点
- 最初的产品假设：不是再做一个"测注意力"的头环 App，而是让专注成为游戏动作的必要条件
- 第一版原型（2026-10-20，commit `be5abe2` "Add dream-pond brain-focusing game MVP"）就确定了核心形态：梦境池塘 + 青蛙 + 荷叶 + 蓄力条

### 1.2 原型怎么跑

```bash
# 仓库根目录
start.command        # macOS
start.bat            # Windows（调用 start.ps1）

# 或手动
python -m uvicorn app.server:app --host 127.0.0.1 --port 8000
```

- 本地地址：<http://127.0.0.1:8000>
- 无设备体验：首页按 `↑ ↑ ↓ ↓ ← → ← → B A B A` → 开发者模式 →「无设备试玩 · 1 分钟」
- 说明：原型是**本地运行**的 Web 应用，没有公网部署；评审需在本机启动

### 1.3 第一版包含什么

| 能力 | 状态 |
|---|---|
| 首页 + 校准 + 游戏 + 报告 + 开发者页 | 有 |
| EDF 回放 / 手动滑块 | 有 |
| 231 维模型 + EMA + 个人基线 | 有 |
| 真机接入 | 无（后续补 OSC） |
| 成长系统 | 无（后续补） |

## 2. AI 辅助开发的方式

- **结对方式**：人定产品规则与验收口径，AI 负责代码草稿、重构、文案与文档；每次改动后用浏览器实测
- **上下文**：先给 AI 看 `README`、`CHANGELOG` 与目标模块，再让它改；避免"整库重写"
- **验证**：能自动测的用脚本/接口验证；不能自动测的（动画、观感、硬件）人工跑一遍
- **失败处理**：AI 生成的改动不做"看起来对就合并"；至少跑一次无设备 E2E
- **记录**：关键决策写进 `CHANGELOG.md`；AI 使用明细见 `AI-USAGE-LOG-dream-pond-focus-frog.md`
